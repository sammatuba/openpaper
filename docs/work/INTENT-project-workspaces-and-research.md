# Implementation intent: research workspaces and reliability

Date: 2026-11-04. Operator authorized autonomous implementation and parallel
subagents after accepting all three strategy priorities. Strategy:
[project workspaces and architecture](STRATEGY-project-workspaces-and-research.md).

## Outcome and scope

Deliver the first useful slice across all three tracks:

1. A finite SELECT-only passage maintenance preview and normal maintenance
   without global trigger changes; meaningful fake and isolated database checks.
2. A shared bounded public HTTPS PDF downloader for browser and MCP import,
   retaining the existing PDF validation and processing pipeline.
3. Reproducible CI for the isolated PostgreSQL/recovery, jobs, Worker, research
   tools and client checks. Preserve explicit refusal of production databases.
4. A local project-workspace CLI supporting a versioned project binding,
   offline diagnostics and a bounded resume packet, with account/project checks
   for online use. Reuse existing dossier/source/paper mappings. Anchor every
   write to an explicitly selected local root; preserve existing authored files.
5. One staged six-to-eight-source collusion prior-work packet, candidate evidence
   ledger and comparison/experiment plan. Scientific claims require actual primary
   source inspection and explicit epistemic labels. No change to the TARA choice.

The existing live collusion project UUID is the initial target. Its existing
collusion directory in ai-safety is the natural binding; no files or hypotheses
are automatically moved. The research packet is staged in this application's
docs/research area for review before any promotion into canonical research.

## Boundaries and failure behavior

- Preserve all pre-existing uncommitted implementation and the three completed
  pilot entries/stale duplicate. No automatic library expansion or stale-job retry.
- No paid inference/search, production maintenance, temporary owner-session
  creation, deployment, commit or push as a side effect of this implementation.
- A source artifact or offline catalog is untrusted data and cannot establish
  current authentication. Diagnostics label offline/connector-observed/online
  checks distinctly. A live pull needs an independently authenticated client.
- Store no tokens, cookies, signed URLs or machine-specific roots in a versioned
  binding. Require explicit root/path containment and reject symlink escapes.
- Preserve existing notes/dossiers. Generated context is bounded and identified
  as a snapshot; no silent two-way synchronization or completeness claim.
- A failure or quota interruption leaves completed artifacts and exact next
  actions recorded. Account-only connector checks remain pending if unavailable.

## Observable acceptance

- Dry run makes no mutations/commits and terminates across multiple batches;
  errors/empty text cannot cause repeated batches. Real isolated checks preserve
  trigger state and validate normal indexing/vector repair.
- Both URL entry paths call the same hardened implementation. Tests cover
  redirect/public-address policy, size/deadline and PDF validation failures.
- CI intentionally starts its own socket-only temporary PostgreSQL and fails
  if expected integration suites are skipped; no live credentials are required.
- Workspace repeat bind is harmless; remote renames preserve UUID identity;
  conflicting account/project/root, path traversal and escaping symlinks fail.
  A generated brief traces to selected local records and declares omissions.
- Research ledger parses, has exact source anchors/hashes and candidate labels;
  quotes are short and checked against inspected sources; no model behavior or
  experimental result is fabricated.
- Run relevant checks and independent MEOS review; resolve material findings
  before completion. Record source/release differences and remaining live checks.

## Parallel ownership

Maintenance agent owns passage script/tests. Download agent owns the shared
downloader, parser/MCP wrappers and downloader tests. Research agent owns only
docs/research/ai-reviewer-collusion. Root owns workspace tooling, CI, work records,
integration verification and review. No overlapping edits are delegated.
